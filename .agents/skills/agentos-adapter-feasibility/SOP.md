# Adapter feasibility SOP

## Inputs and entry

Requested provider, verified executable/distribution, installed version, official protocol references, requested capabilities, isolated workspace, scoped session ownership and an overall call/time/cost budget. Read prior capability results before rerunning probes.

## Permitted actions

Inspect official docs and CLI help, run bounded local protocol checks, and perform only the synthetic model/control experiments authorized for owned test sessions. Export allowlisted metadata and versioned results, not raw streams.

## Prohibited actions

Do not install an unknown CLI or SDK, scan unrelated private histories, extract credentials into fixtures, attach/control existing sessions, bypass provider approvals, generalize context resume to running-process pause, or advertise untested support. A new provider name does not establish its executable, package or native skill paths.

## Procedure

1. Check whether existing evidence already answers the requested capability at the relevant version/scope. Revalidate only material drift or missing evidence.
2. Confirm provider identity and official source. For Antigravity, resolve that identity before choosing commands or suggesting installation.
3. Define the overall experiment budget across all attempts, ownership boundary and cleanup; required live-operation authorization precedes inference/control.
4. Test observation and error paths before controls. Check authentication readiness with metadata only; after an auth failure, stop inference retries until readiness changes.
5. Correlate exact session/turn identifiers and terminal results. Acknowledgement alone is insufficient. Preserve disconnect/unknown semantics, duplicates, ordering limits and replay gaps.
6. Sanitize before saving. Report each capability as verified, unverified, blocked or documented unsupported with version/scope. Clean up only probe-owned transient resources; retain user data and provider settings.

## Stop or hold

Hold on unknown provider identity, missing auth/permission, exhausted budget, repeated unchanged failure or ambiguous session ownership. Continue other independent approved work; do not spend another run's budget to evade the overall cap.

## Exit and evidence

Publish bounded capability observations, command/check results, versions, limitations, cleanup and the next specific experiment. Synthetic evidence is not production support. Keep untested providers in the queue without adding fake UI controls or native discovery claims.
